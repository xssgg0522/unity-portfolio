02 / RESOURCE PIPELINE

AssetBundle 资源热更新

核心项目

这是资源热更新，不是 C# 代码热更新。重点在“版本清单 + MD5 增量 + 异步下载 + 旧包清理”这一套链路。

我做了什么

  • 用 EditorWindow 收敛平台切换、清单生成、首包同步和 FTP 上传。
  • 清单记录文件名、大小、MD5；客户端按 MD5 生成新增 / 变更 / 待删除列表。
  • 首次安装回退 StreamingAssets，后续读取 persistentDataPath。
  • FTP + Task 异步下载，最多 5 轮重试，带进度与结果回调。
  • 更新完成后回写本地清单，清理远端已下线的旧 AB。
发布端ABTools
客户端ABUpdateManager
清单name / size / MD5
01

版本清单是唯一依据

客户端不猜版本，只按清单里的 MD5 判断：没有就新增，不同就更新，相同就跳过。

02

异步不卡主线程

FTP 和文件读写放进 Task.Run，await 回到主线程再回调 UI。

03

旧包也要清理

远端遍历完后，本地剩下的 key 就是已下线资源，直接从 persistentDataPath 删除。

03 / UI FRAMEWORK

xLua UI 框架与背包系统

核心项目

把面板生命周期、控件绑定、Lua 打包和背包数据拆成可复用的层次，减少每个面板重复写加载和查找。

框架设计

  • Object → BasePanel 两级继承，统一面板加载、显示、隐藏。
  • C# 反射 + GetComponentsInChildren，按 txt/img/sV/tog/btn 前缀自动扫描控件。
  • 控件按“名称 + 类型”缓存，新增面板只写业务逻辑。
  • XLua Editor 扩展：Lua 脚本批量转 .txt 并自动设置 AssetBundle 标签。
  • 背包 JSON 配置转 id 字典，ItemGrid 只依赖 id 取图标和数量。
框架Object / BasePanel
背包BagPanel / ItemGrid
数据ItemData / PlayerData
01

命名规范即接入协议

控件按前缀命名即可被扫描到，新增面板不用手写一堆 Find。

02

配置与表现分离

JSON 只提供 id、图标名、数量；ItemGrid 负责把数据变成格子。

03

格子复用

同一套 prefab 和图集服务三个页签，切换时销毁旧格子、按 4 列重建。
